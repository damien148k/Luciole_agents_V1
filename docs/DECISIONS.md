# Décisions techniques

Une ligne par choix : ce qu'on a décidé, pourquoi, quand. On ne rediscute pas un choix noté sans nouvelle mesure ; si on change d'avis, on ajoute une ligne, on ne réécrit pas l'ancienne.

| 2026-10-18 | Une valeur de métadonnée invalide n'est jamais corrigée en silence : elle est refusée et signalée (erreur, ou avertissement si une autre source a comblé le champ) ; un document incomplet est gardé et signalé, pas écarté | Le cas commerciaux compte et filtre : un « gagné » deviné fausserait les comptages ; garder le document laisse Damien corriger la source |
| 2026-10-18 | Tokens comptés par le tokenizer du modèle d'embedding (`tokenizers`, fichier `tokenizer.json` lu dans le cache local ou `LUCIOLE_MODELS_DIR`, jamais téléchargé) derrière un contrat `TokenCounter` ; compteur factice dans les tests unitaires | Les tailles sont celles que BGE-M3 verra ; les tests restent hors ligne et rapides |
| 2026-10-18 | Découpage parent-enfant sur les nœuds : parent = une section (≤ `parent_size_tokens`, jamais à cheval sur deux sections), enfant ≤ `size_tokens` avec recouvrement pris dans les derniers blocs ou phrases ; contexte « Titre > Section » devant chaque morceau, ≤ ¼ d'enfant, compté dans `max_tokens` | On cherche et cite un passage court, on fait lire la section ; le contexte améliore le rappel (spec d'ingestion) |
| 2026-10-18 | Garde `max_tokens` : un dépassement lève une erreur, aucun texte n'est tronqué en silence ; un bloc trop long est coupé (tableau par lignes avec en-tête répété, puis phrases, mots, caractères) | Porte de l'étape 2 ; un morceau tronqué par l'embedder perdrait du texte sans trace |
| 2026-10-18 | Numéros de page imprimés : ligne de marge qui n'est qu'un numéro (« 7/47 », « 12 »), retenue si elle revient sur assez de pages avec des valeurs qui changent ; un par moitié de double page ; les blocs Markdown sont rattachés à leur moitié en retrouvant leur début dans le texte natif | Mesuré sur les 3 études publiques : numéro trouvé sur 185 pages sur 202 (toutes sauf couvertures et sommaires), 93 % des blocs des doubles pages rattachés à une seule moitié |
| 2026-10-18 | Un morceau porte les métadonnées du document, pas celles du dossier | L'issue d'un dossier change sans que ses réunions changent : on filtre par dossier via le magasin structuré ; à revoir à l'étape 3 si Qdrant doit filtrer seul |
| 2026-10-18 | Qdrant 1.19.1 et OpenSearch 3.8.0, images épinglées par version et par empreinte de liste multi-architecture (amd64 + arm64) ; clients `qdrant-client` 1.19 et `opensearch-py` 3.2 | Versions récentes et stables pour les trois machines ; Qdrant ≥ 1.10 garde ouverte la voie multivecteur (V5 était bloqué en 1.7.4) |
| 2026-10-18 | Index : seuls les morceaux enfants sont indexés ; Qdrant porte deux vecteurs nommés (`content` = passage, `context` = « Titre > Section » + passage) ; OpenSearch analyse `text` et `context` en français ; parents et morceaux complets gardés dans le magasin SQLite (schéma 2) | On cherche sur des passages courts, on relit la section dans le magasin ; V5 mélangeait contexte et contenu dans un seul vecteur |
| 2026-10-18 | Clé d'index (schéma, profil d'embedding, modèle, dimension) notée par document dans le magasin et intégrée au nom de collection ; une clé différente réindexe le document dans un nouvel index | V5 réutilisait une collection existante sans vérifier ni dimension ni modèle |
| 2026-10-18 | Ordre d'écriture : index (suppression par `document_id` puis écriture) avant magasin ; un document n'est noté indexé qu'après | Un arrêt au milieu d'un passage ne laisse ni doublon ni document noté à tort comme indexé : le passage suivant le refait |
| 2026-10-18 | Modèles listés dans `configs/models.yaml` avec une révision = commit complet ; récupérés une fois (`DEV.ps1 -Action models`) dans `LUCIOLE_MODELS_DIR` (défaut `models/`), avec un fichier `luciole-model.json` (révision, tailles) relu hors ligne ; un modèle incomplet ou d'une autre révision est refusé, jamais téléchargé en fonctionnement | V5 lisait le cache Hugging Face sans savoir quelle révision il contenait ; la révision entre dans le nom de l'embedder, donc dans la clé d'index |
| 2026-10-18 | BGE-M3 : vecteur dense seulement, via `sentence-transformers` 6.1 et PyTorch 2.14 dans l'extra `embed` (jamais en CI) ; ni poids sparse ni ColBERT récupérés ; le profil de cas d'usage nomme le modèle (`embedding.model`) | Leçon de V5 : ne pas embarquer ce qu'aucun code ne charge ; l'extra garde la CI légère |
| 2026-10-18 | GPU par le profil matériel, sans repli silencieux : un profil `cuda` sans GPU visible lève une erreur claire. PyTorch vient de PyPI (CUDA inclus sous Linux, processeur seul sous Windows) ; le GPU passera par l'image Docker Linux | L'index CUDA de PyTorch est injoignable depuis le conteneur de Claude, donc impossible à verrouiller dans `uv.lock` ; sous Windows, les tests du vrai modèle tournent sur le processeur |
| 2026-10-18 | Watcher à un seul fil : relevé périodique (chemin, taille, date) toutes les `ingestion.watch_interval_s` secondes, passage du pipeline quand le relevé a changé et qu'il est stable deux fois de suite ; échec retenté avec une attente qui double (plafond 10 min) ; un verrou de fichier du système (`msvcrt` / `fcntl`) par magasin. Ni `watchdog`, ni minuteries, ni file de travaux | La panne de V5 du 3 août 2026 venait de minuteries concurrentes sur une connexion SQLite partagée ; le relevé fonctionne aussi sur un dossier Windows monté dans Docker, où les notifications ne passent pas ; le pipeline est déjà le réconciliateur |

| 2026-10-18 | La clé notée par document (`document_key`) ajoute à la clé d'index la version du parser et l'empreinte du profil (entités, ingestion, découpage, modèle) ; la collection reste nommée par la clé d'index | Changer une taille de morceau ou une règle de métadonnées réindexait jusqu'ici seulement les fichiers modifiés |
